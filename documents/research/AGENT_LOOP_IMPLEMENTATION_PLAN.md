# Agent-driven research loop: implementation plan

**Date:** 09 October 2026

**Revision:** 1.3 — scoped data requirements and bounded Mini evaluation; aligned with architecture 2.10.2. Historical Astra executions retain their original identities.

**Status:** The bounded Research/Discovery–Critic workflow, append-only registry, restricted worker, operator admission and fixed-catalog development path are implemented. Astra and Mini have completed real proposal/critique runs. The v2 Mini step exercised scoped data requirements, 24 process regressions and one proposal; that proposal was rejected as a duplicate. New independent economic evaluation, broad research-quality benchmarking, MCP, RAG and promotion remain pending. See the [Astra execution](evaluations/agent_loop_bootstrap_20261009/REPORT.md), [Mini execution](evaluations/mini_requirements_20261009/REPORT.md) and [operations guide](../operations/RESEARCH.md).

This plan implements the first product slice in [ARCHITECTURE.md](../ARCHITECTURE.md), Section 14. Its outcome is an actual model-driven proposal, a separately recorded critique, a contract decision and evaluator-owned evidence. The agents generate and challenge research ideas; the registry and evaluator determine what was proposed and measured. The [Research Kernel plan](RESEARCH_KERNEL_PLAN.md) owns the source measurements and the two completed EURUSD diagnostics. The [data-availability record](../data/DATA_AVAILABILITY.md) owns unresolved source and broker-quote questions.

## 1. Starting state and bounded first use case

The repository currently has an isolated live-capture service, PostgreSQL/Alembic for capture data and an offline EURUSD case-audit/evaluator path. The [2020 diagnostic](evaluations/eurusd_four_hour_direction_2020_v1/evaluation/evidence.json) narrowly passed a predictive gate; its [2021 replication](evaluations/eurusd_four_hour_direction_2021_replication_v1/evaluation/evidence.json) failed temporal validation. Both outcomes are released prior research. Their validation windows are consumed, their source visibility is retrospective, and neither measured executable net payoff. The local raw CSV is accessible to the offline research code, so the current phase split is not a holdout access boundary.

The first agent run uses EURUSD source coverage, the released structured evidence and a declared development view. Research/Discovery proposes **one** new Loop B decision/payoff contract per run; Critic returns **one** typed review. There is no unbounded debate or automatic search expansion in this slice. Every run records its configured model, tool and resource budgets before invocation. An unsupported payoff is rejected; a scientifically plausible proposal that lacks required data is retained as `BLOCKED_DATA_REQUIREMENT` with its missing source and reactivation condition. Neither result is a measured failure of economic value. A new validation window and any economic success gate belong to the eventual frozen hypothesis, not to this implementation plan. This price-only slice tests agent orchestration and research discipline; it cannot establish the value of future news/semantic agents or the discovery ability of an unrestricted researcher.

The first slice has no order placement, portfolio allocation, strategy promotion or live Executor. The same agent runner and evidence contracts later support Loop A and a shadow Executor without changing who owns risk or measured outcomes.

**Implementation entry decision.** Start with one supported, typed EURUSD **price-only fixed-horizon directional diagnostic** family using the existing source and evaluator conventions, with no order or net-payoff claim. A materially new decision timing, target or horizon is Loop B; a rule variation under an unchanged target/payoff is Loop A and needs a registered baseline. The contract service admits only event-selection rules and calculations implemented by a reviewed evaluator version; the agent cannot submit executable code or extend the evaluator schema by prose. Before accepting a first proposal, freeze this catalog's schema, permissible development source view, baseline rules, trial/resource budget and chronological holdout-allocation policy. Import the 2020/2021 attempts as released prior evidence, not evaluation windows. Historical and prospective economic hypotheses may be recorded, but remain blocked until their source and cost contracts are supportable.

## 2. Ownership and end-to-end flow

| Owner | May do | Cannot do |
| --- | --- | --- |
| Research/Discovery agent | Read permitted development/source material and released evidence; submit a typed hypothesis draft, rationale and ex-ante forecasts. | Read sealed validation outcomes, assign authoritative family identity, freeze its own contract, write measurements or choose success after results. |
| Critic agent | Read the draft and the same permitted evidence; submit typed objections, missing-evidence findings, predicted risk and review disposition. | Rewrite the draft silently, measure validation, approve promotion or change account risk. |
| Contract service and reviewer | Validate supported decision, feature, payoff, cost, data-sufficiency, universe, windows, gates and trial budget; resolve ancestry/duplicate candidates; append freeze, blocked or rejection events. | Infer missing economic costs, silently treat a new name as an independent family or modify a frozen contract. |
| Independent evaluator | Read a frozen contract and sealed validation data; compute case-level outcomes and typed evidence. | Accept model text as measured evidence or change the registered target/gates. |
| Research registry | Own stable identities, immutable versions, proposal/critique/freeze events, trials, evidence references and released status. | Treat a RAG summary or frontend projection as authoritative evidence. |

The workflow is `registered agent versions → bounded Research proposal → Critic review → ancestry and contract review → immutable freeze, block or rejection → evaluator-owned result if eligible → explicit release → later agent context`. Each transition has an actor, time, input references, output hash, status and reason. A policy or authorized reviewer decides whether a draft is admitted; the contract service validates and freezes the exact admitted content. Rejected, blocked and abandoned proposals remain queryable. An accepted proposal only reaches validation after its candidate, data policy, source view, windows and gates are frozen. The evaluator receives the candidate through a typed contract, never executable code authored by a model.

Make the two commitments explicit: **design freeze** records the question, catalog/search space, development objective, baseline-selection rule, inference policy and budgets before new development measurements; **candidate lock** records the selected exact rule/parameters, fitted transformations and baseline after development, before validation access. With no parameter search these can be consecutive events, but their responsibilities remain distinct. A bounded development job uses the same reviewed calculation catalog as the evaluator and records every tried candidate. A changed design after development results creates a child attempt with that exposure preserved. The first authorized contract reviewer is an operator using typed commands; a third LLM or a separate distributed service is not required.

Critic runs in a fresh context containing the submitted draft and eligible evidence, without the proposer's private conversation, hidden reasoning, provider name or unneeded self-rating. Its review is recorded separately, but separate roles or different model providers do **not** establish statistically independent errors. Critic advice cannot substitute for deterministic checks or measured evidence; test what it actually catches. The empirical motivation and its limits are recorded in Section 8.

## 3. Minimum contracts and storage

Implement domain types before API or MCP wrappers. Use an Alembic migration when each durable responsibility is implemented; keep source payloads and large model inputs as immutable artifacts with hashes and access-controlled references. PostgreSQL owns identities, constraints and event relationships, with schema-validated JSON only for bounded extensible contract payloads.

| Contract | Minimum durable fields |
| --- | --- |
| Agent version | `agent_id`, role/capability, immutable version, instruction hash, output-schema version, exact model-profile binding, allowed tool-policy version, run and research-budget policy, and publication status. |
| Agent run | `run_id`, agent version, parent/workflow ID, task and evidence-snapshot IDs, started/completed times, result status and failure reason. |
| Model invocation | Run/step ID, provider endpoint and returned model identity, exact input reference/hash, output reference/hash, parameters, timing, usage and error/refusal. |
| Tool invocation | Run/step ID, tool/schema version, caller scope, argument/result references and hashes, authorization decision, timing and error. |
| Hypothesis draft and critique | Stable draft and suggested parent IDs, complete typed contract proposal, author run, source references, pre-outcome belief/forecast record; critique ID, cited draft version, typed objections, predicted risk and disposition. |
| Freeze, trial and evidence | Design-freeze and candidate-lock hashes/times; catalog, evaluator and inference-contract versions; trial/search-family identity and budget; evaluator run, case-artifact hashes, measured fields, typed failure, integrity and release status. |
| Family, exposure and budget | Service-assigned family ID, normalized contract signature, parent/related/exposed links, reviewer decision and rule version; campaign ID; separately reserved/spent proposals, revisions, evaluated candidates, model/tool resources, validation exposures and statistical error allocations. |
| Inference contract | Estimand, population/case weighting, primary endpoint and comparator, minimum relevant effect, uncertainty/test method and assumptions, multiplicity scope/allocation, inspection/stopping rule, minimum support and release rule. |
| Process-evaluation suite | Task/family split, source snapshot, reference labels and their author, rubric/judge version, experimental arms, repetitions, resource limits, missing/refused-run treatment and frozen comparison rule. |

Import or register the 2020 and 2021 offline attempts by their existing hashes and original evidence modes; preserve the original files and timestamps. The family view counts both attempts even though each historical evidence file reports one trial within its own frozen hypothesis. The import must not upgrade those files to prospective evidence or certified economic results.

The Research agent may suggest ancestry, but the contract service assigns the authoritative family and exposure links. First compare normalized target, action, event rule, instrument, horizon, feature/source lineage, baseline and cost assumptions using deterministic rules. Semantic similarity may flag near duplicates for an authorized reviewer who is not the proposer; its score alone cannot create a new family or declare independence. Record relations as `SAME_ATTEMPT`, `VARIANT`, `RELATED_EXPOSED` or `DISTINCT`, with reason and rule/reviewer identity. A three-hour volatility-conditioned EURUSD momentum idea is at least a variant of a four-hour momentum family; a news-conditioned continuation idea may be distinct in mechanism yet still related/exposed to that family's released results. Ambiguous overlap remains `RELATED_EXPOSED` for holdout accounting until reviewed. A renamed or lightly modified proposal cannot reset the trial budget or reclaim a consumed window; cross-family exposure is separately recorded even when contracts are substantively distinct.

Recorded-output replay reads captured model/tool outputs for the exact run fingerprint. Fresh inference creates a new run and cannot overwrite the original. Persist exact assembled model input or an immutable access-controlled reference before invoking the provider; retain tool arguments/results and their order. Record requested alias, provider-returned model identity if supplied, endpoint, request parameters, invocation time and periodic fixed-input canary results. An alias or silent hosted-model change may make fresh inference non-reproducible; changed prompt, tool policy, retrieval snapshot or detected model behavior creates a distinct effective evaluation/deployment epoch. A canary detects some drift but does not prove identical model weights.

### Durable transitions and evidence corrections

Reserve budgets and validation windows transactionally before work starts. Concurrent runs cannot spend the same remaining allowance or reserve the same window independently. Persist a job/invocation intent before dispatch, then append completion, failure or interrupted/unknown status. A provider timeout does not prove that no request ran or incurred cost; reconcile usage where possible and retain conservative reservations where it remains unknown. Any new provider attempt gets its own invocation ID and resource charge. Re-delivery of the same application command is idempotent and cannot create a second draft, result or exposure. These are database/job semantics within the first slice, not a requirement for a new message broker.

Keep research status separate from evidence integrity. A discovered source, evaluator or import defect appends an invalidation/supersession event with its reason and affected hashes; never edit away the old result or restore its consumed holdout. Materialized views and future retrieval exclude invalidated evidence from current support and flag dependent lessons, freezes and eligibility decisions for review. Historical replay preserves the evidence state actually used then. A repaired calculation is a linked correction on already exposed data, not a fresh replication; re-execution policy and publication authority must be explicit.

### Research feedback contract

Record **why the proposer believed the idea before seeing outcomes** as a concise, testable artifact: proposed mechanism, expected direction and horizon, observations supporting it, contrary evidence already known, key assumptions, predicted failure modes and what would falsify it. Add separately scoped ex-ante forecasts for contract admissibility, temporal gate and net-cost gate only where each target is defined; record the target, forecast probability, cutoff time and whether it will ever be resolvable. These are subjective forecasts until calibrated across enough independent resolved attempts. References identify the source snapshot and released evidence available to the run. This is an explicit proposal rationale, not a request for hidden model reasoning. The Critic records which assumptions it challenged, which evidence it used and its predicted failure mode. Subsequent revisions create linked draft versions; neither rewrites the earlier belief record.

An evaluation records separate dimensions: technical/data evaluability, predictive or gross effect, temporal/breadth transport, executable net payoff, tail/calibration behavior where relevant and prospective status. Retain measured values, uncertainty, support, baseline and cost assumptions even when a gate fails. Store the gate that failed and one or more typed reasons; distinguish an **unmeasured or blocked** dimension from a measured negative result. `COST_FAILURE` requires a credible frozen cost calculation showing the registered economic gate failed. Unknown spread or missing fill data is `COST_UNVERIFIED` or `DATA_QUALITY_FAILURE`, not evidence that the signal has no gross value. A plausible, untestable proposal receives `BLOCKED_DATA_REQUIREMENT` with source/quality requirement, owner and recheck trigger; it is reactivated by a new status event when data arrives, never rewritten as an earlier validation. `TEMPORAL_FAILURE` rejects this frozen rule under this registered validation, not every related research question.

Success is likewise scoped: `DEVELOPMENT_SURVIVOR`, historical validation pass, net-cost pass and prospective pass are separate claims with distinct source and time modes. A source-coverage pass or a schema-valid model response is not a trading success. For family-level accounting, count every draft, revision, rejection, abandoned attempt, failed evaluation and optimizer trial while retaining each attempt's exact stage and reason; do not inflate the historical 2020 and 2021 files' per-hypothesis `related_trial_count` when importing them. Their family view counts both inspected attempts.

After evaluator release, a versioned lesson writer may create a short **derived** explanation with `lesson_id`, source proposal/critique/evidence IDs, exact supported claim, applicability boundary, contrary or unresolved evidence, author/version, creation time and review status. A lesson can say, for example, that a measured gross effect failed a particular cost contract; it cannot turn `COST_FAILURE` into “the underlying idea was nonsense.” Corrections append a new lesson version. Group all lesson versions and summaries by their root evaluation/evidence IDs when retrieving or counting support: ten narratives from one failed trial are **one evidence lineage**, not ten independent replications. The registry remains the source of measured truth; an agent must be able to open the cited typed record from every retrieved lesson.

## 4. Tool boundary and optional MCP surface

Implement the following as typed application-service operations used directly by the first in-process agent runner. Add a narrow MCP adapter over the same services **only when a selected agent host requires it**; MCP does not own domain state or gate the first workflow. Each operation has a bounded input/output schema, pagination or size limit where needed, caller scope, version, audit event and explicit error types. [MCP architecture](https://modelcontextprotocol.io/specification/2025-11-25/architecture) · [MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

| Initial operation | Research/Discovery | Critic | Result |
| --- | --- | --- | --- |
| Read source coverage and provenance | Read | Read | Source/artifact IDs, hashes, timing assumptions and limitations; no arbitrary path argument. |
| Read released evidence by hypothesis/family | Read | Read | Typed measurements, status, evidence mode, trial count and immutable references. |
| Read permitted development snapshot | Read | Read | Bounded case/context view after authorization and time filtering; no sealed validation target. |
| Submit hypothesis draft | Write proposal only | No | Versioned draft ID or typed validation error. |
| Submit critique | No | Write review only | Versioned critique ID or typed validation error. |
| Request contract review | Request | Request | Freeze eligibility, `BLOCKED_DATA_REQUIREMENT` or typed rejection from the contract service; no self-issued success status. |

Use service identities and scopes to enforce these rights at the data access boundary. The research worker must not mount or possess credentials for sealed validation artifacts. The evaluator runs under a separate identity with access to the frozen candidate and validation data, and writes measured evidence through its own service contract. A model cannot obtain broader access by altering prompt text, MCP tool names, resource URIs or retrieved content. Tool annotations are descriptive hints; the server enforces authorization, budgets and input validation. No generic SQL, unrestricted filesystem, broker-order, evidence-write or promotion tool is exposed to these roles.

Enforce the same scope for logs, exception messages, caches, artifacts and provider-facing payloads. The initial runner has only its permitted snapshots and configured provider endpoint; broad web search is not an initial research tool. External literature is imported through an explicit, provenance-preserving path when needed. Exercise adversarial retrieved text, fabricated evidence IDs and requests to change gates or reveal sealed artifacts, alongside benign tasks. Check denied actions and data access in service logs and stored state; a model's statement that it obeyed is not the test oracle. Prompt-injection benchmark results motivate these checks, without certifying this implementation's robustness (Section 8).

The first retrieval policy can use structured registry queries and bounded source records. Market-knowledge RAG and research-knowledge RAG remain separate when added; each retrieved artifact carries source, version and `available_at` or a clearly labelled retrospective visibility rule. Episodic memory becomes eligible only after its required outcomes are known. Neither RAG nor memory may supply a historical agent run with later validation outcomes as if they existed at decision time.

### How later agent runs use released evidence

Start with **structured evidence feedback**, without embeddings: query the registry by research family, decision/payoff type, instrument, horizon, source and typed failure stage; return the complete relevant attempt counts, measured fields and evidence modes. Released 2020/2021 results are eligible as prior research, but are never a fresh holdout. The next Research run must identify which prior facts it used, which lessons it treated as tentative and how its new proposal differs from consumed attempts. A duplicate with a cosmetic new name is rejected or linked as a revision. Critic checks whether the proposal misstates or omits relevant negative results.

Research RAG later indexes literature, methods, reports and **reviewed, model-friendly lessons** as derived explanations. It may help an agent discover a mechanism or interpret why an attempt failed, but every result claim resolves to registry IDs. Episodic research memory is a narrower record of a particular proposal → critique → outcome → lesson episode; it is written only after the necessary outcome is released. Keep versioned retrieval policies, bounded context, exact retrieved IDs/order and eligibility times. Retrieval should include relevant counterexamples and near misses rather than ranking only successes; report missing comparable evidence instead of manufacturing a precedent. Do not place research lessons in the Executor's market-knowledge RAG by default.

Model-weight training is deferred. First compare a no-feedback agent against structured evidence feedback, then optionally against structured evidence plus Research RAG/episodes on matched, predeclared research tasks. Measure citation accuracy, correct failure interpretation, duplicate avoidance, contract completeness, Critic detection of unsupported assumptions, valid frozen proposals, independent evidence yield, latency and cost. Store every proposal, including nulls, and assess whether the added context improves the **research process**, not just the apparent backtest score. If enough diverse, reviewed examples later exist, a versioned fine-tuning attempt can target bounded behavior such as contract completeness or failure-taxonomy interpretation. It needs a separately held-out family/time evaluation and a supported provider; binary “winner/loser” labels or training on unreleased validation outcomes are unsuitable.

Keep feedback arms isolated: fix each evidence/memory snapshot at run start and prevent one arm's critique, lessons or outcomes from entering another. A lesson's causal explanation remains a hypothesis unless the source experiment identified that cause. Reflection improving a benchmark does not establish that a trading mechanism was learned. For the first suite, include cases where a gross effect fails costs, where required data are absent, and where corrected evidence invalidates an earlier lesson. When revisions are enabled, measure correctly detected defects, repairs and newly introduced defects separately; retain the first proposal and the alleged versus independently supported defect. Verify that feedback preserves these distinctions and improves the registered task metrics before expanding memory (Section 8).

### Holdout inventory and depletion rule

Physical separation prevents unauthorized outcome access; it does **not** renew a window after its results influence research. Maintain an evaluator-owned inventory for each source, instrument and period with source snapshot, coverage-only eligibility, evidence mode, access scope, allocated research family, registered use/budget, first outcome access, release time and state (`AVAILABLE`, `RESERVED`, `CONSUMED`). The 2020 and 2021 EURUSD outcomes enter as `CONSUMED`. Unknown prior access makes a window ineligible until reviewed; it is not silently initialized as available. Register the window-allocation rule and family trial budget before selecting a candidate from development evidence. A coverage scan may establish whether a window has sufficient rows, but may not compute the candidate's labels, returns or performance. Keep detailed validation features and outcome-eligibility diagnostics evaluator-side if they could reveal target information; research receives the approved coverage summary only.

All candidates evaluated on one reserved window share **one exposed validation resource**. Predeclared batch comparisons may be reported together, with their multiple-testing burden, but are not independent replications of each other. Once any result from that window is inspected or released, later revisions in the family treat it as development evidence. A renamed contract, slightly changed horizon or new agent prompt does not restore its independence. Record cross-family exposure when a released result could inform another family. Never select the next window because its candidate outcome looked favorable; use a predeclared chronological/allocation policy and report the whole sequence.

When no credible unused historical window remains, stop claiming fresh historical validation. Freeze the contract before future observations arrive and gather **prospective** shadow evidence with its actual registration and start times; later prospective windows can be allocated in sequence under a declared policy. If the current source lacks adequate cost or timing semantics, keep the claim at predictive/retrospective scope or collect the missing prospective broker observations. A typed `NO_INDEPENDENT_WINDOW` blocker preserves the proposal without inventing a pass or consuming a known window again.

**Project exposure and model knowledge are different facts.** An inaccessible CSV does not establish that a model never learned the corresponding public events or market regime. Record known pretraining/post-training exposure bounds and their provenance, `UNKNOWN` where unavailable, model-inference time, allowed external knowledge and project exposure separately. Current-model analysis of historical news, or historically tailored proposal generation, remains retrospective with possible model-knowledge contamination. A deterministic price-rule evaluator reduces direct LLM label leakage but cannot certify unbiased hypothesis selection. Date/entity masking can be a registered diagnostic, not proof of clean data. Prospective predictions must be recorded before the outcome; later fresh inference cannot replace a missing prediction. Financial sentiment research documents both future-knowledge and distraction effects, rather than a universal upward bias (Section 8).

### Statistical claims and prospective inspection

Logging all attempts is necessary audit history; it does not itself control false discoveries. Before independent validation, freeze an evaluator-owned **inference contract**. It identifies the primary estimand and case weighting, baseline, minimum effect worth detecting, primary versus descriptive metrics, uncertainty method and assumptions, support requirement, and the claim being tested. A failed superiority gate is not proof of no effect; an underpowered or inconclusive result retains its interval and reason. A claim of equivalence or futility needs its own predeclared margin/rule. Existing 2020/2021 gates remain as originally measured and receive no retroactive statistical certification.

Group confirmatory claims in a service-owned **campaign** that includes related families, agent variants, endpoints and planned looks. The campaign's statistical error allocation is distinct from its token/trial budget; splitting family IDs does not create fresh allowance. Start with a finite set of planned tests and one outcome inspection per validation allocation. Use a reviewed fixed allocation or multiplicity procedure with valid component tests under the declared dependence assumptions; record unused, reserved and spent allocations. For example, a finite Bonferroni allocation does not require independent tests, but cannot repair invalid individual tests. A draft rejected without an outcome remains a search/resource event, not a fabricated statistical test. If valid inference is not supported, publish exploratory measurements with no confirmatory pass claim. Methodological basis and limits: Section 8.

For the first prospective test, fix the collection end, settlement/maturity lag, minimum eligible support and one terminal performance release before collection starts. Insufficient support at the end remains inconclusive; do not extend because a result is close to passing. Feed-health monitoring may continue, but interim candidate performance is sealed. An operational stop is retained as interruption, never a successful early stop. Early peeking consumes the allocation and invalidates its fixed-look claim. Future sequential monitoring requires a separately reviewed, time-uniform method or predeclared group-sequential spending rule with justified market-dependence assumptions; ordinary confidence intervals inspected every day are not that method.

### Broker-cost evidence gate

The [data-availability record](../data/DATA_AVAILABILITY.md) now identifies a local 2026 live-account HTML statement. Its entry/closing executions and net results are observed account evidence, but its export omits separate commission, swap, gross result, opening time and deal/order IDs. It cannot identify historical 2020 executable spread or validate the zero-spread broker-tick fields. Treat the 2026 sample as a starting point for **prospective cost calibration**, not a substitute for a dated 2020 cost contract.

Before freezing an economic cost contract, record the exact broker entity, account type, symbol, size, trading session, effective fee dates, spread source, commission and financing terms, conversion assumptions, requested and filled order prices/times, fill/rejection model, and stress ranges. Seek detailed deal-level exports and reconcile gross, fees and net against the statement; pair fills with contemporaneous bid/ask or broker market snapshots to measure spread and slippage. Keep observed costs, historical broker terms and hypothetical stress assumptions as separate evidence modes. If credible costs for the claimed interval remain unavailable, preserve the proposal as a predictive diagnostic or a cost-unverified candidate; no `COST_FAILURE`, net-payoff pass or promotion claim follows from guessed charges.

### Evaluate the researchers, Critic and stopping policy

Research quality is a **vector, not a pass rate**. Under a frozen task set and evidence snapshot, record contract validity, lineage-aware novelty/duplication, falsifiability, whether the proposed test can resolve a material uncertainty, research cost and the yield of independently measured evidence. A negative but decisive result may be useful; a stream of easy, low-information passes is not proof of discovery skill. Novelty and expected information gain are reviewed against a predeclared question and prior family evidence, never inferred from an attractive post-outcome story. Score each ex-ante probability against its exact resolved gate using a proper scoring rule and calibration plot once enough independent resolved forecasts exist; blocked/unobserved targets remain censored rather than scored as failures. Report denominators and uncertainty instead of one opaque agent ranking.

Freeze the proposal-quality assessment from the information available **before** evaluation outcomes. A well-formed, novel and falsifiable proposal can fail its payoff gate without becoming a bad research decision; a lucky positive result from an invalid or leaky contract remains a bad research decision. Keep that process assessment, evaluator measurements and later economic outcome as separate linked records. The same rule later applies to Executor decisions and broker fills, as specified in [ARCHITECTURE.md](../ARCHITECTURE.md), Section 5.3. Outcome-aware diagnostics may explain systematic errors but cannot rewrite the original ex-ante assessment.

Critic quality is separately measured. Record each objection's cited evidence, predicted failure type, severity and recommended action before contract review. Audit a preselected sample of rejected or blocked drafts with independent reviewers and, where feasible, bounded development or later prospective checks; do not spend sealed holdouts merely to estimate Critic recall. Compare matched proposal batches with and without Critic at the same research budget. Measure supported-objection precision, invalid-contract detection, wasted-work avoidance and rescued promising ideas. Because most rejected ideas have no independent outcome, label false-rejection estimates as incomplete or censored. A high rejection rate alone is neither success nor failure.

Audit **accepted drafts as well as rejected drafts** against known contract defects and reviewer-labelled examples. Measure missed defects conditional on proposer errors; shared blind spots are more relevant than whether the two agents sound different. Use deterministic scoring for contract/schema/citation checks. For judgement such as novelty and falsifiability, freeze a rubric, reference examples, reviewer identity and disagreement procedure; keep uncertainty visible. If an LLM judge is introduced, blind provider/agent identity and later payoff, vary presentation order where applicable, and check agreement on held-out human-labelled examples. Agreement with another LLM is not ground truth. Freeze the pre-outcome assessment before releasing evaluation results.

The first process benchmark compares a single Research agent, Research + Critic and a simple checklist or bounded resampling control under the same total allowance. When the catalog is finite, include a fixed or seeded non-LLM catalog-selection baseline where it answers the same task. This distinguishes useful research assistance from extra sampling or deterministic checks. Predeclare paired tasks, independent run repetitions, aggregation, provider-time blocking and refusal/timeout treatment; retain every run, without best-of-run reporting. Cost includes the Critic, retries, retrieval and evaluator work. Compare feedback policies separately before attempting a large factorial study. Agent benchmarks motivate these controls, not an assumption that the simplest arm will win (Section 8).

Keep process-suite development cases separate from held-out tasks/reference labels used to compare agent versions. Prompt/rubric tuning against a test result consumes that process test too, even when no market holdout is involved. Split related templates/families together, version the suite, and replenish it when exposed. Artificial cases with planted errors test workflow competence only; label them as fixtures and never add them to economic evidence. The first suite can remain small, but it must state which behaviors and independent tasks it actually covers.

Before a family begins, freeze maximum drafts, revisions, optimizer trials, model/tool calls, tokens or equivalent provider usage, wall time, monetary cost and independent-window exposures. Any staged budget increase needs a predeclared development-only trigger and an authorized allocation event; record all spent resources. Compare agent versions on matched tasks, released evidence, provider conditions and **equivalent budgets**, or report a cost-quality frontier instead of a winner. Select and freeze a candidate when its development search ends. Mark a family `EXHAUSTED` when its budget, valid testable space or available independent windows are spent, or when a predeclared futility rule fires. Reopening needs materially new source evidence, a prospectively allocated window or a changed contract with explicit ancestry and a new approved budget; renaming does not reset the counter.

### Unit of independent evidence

Every payoff contract specifies the unit on which outcomes may be correlated: for example a decision, UTC day, event, central-bank meeting or broader regime. The evaluator reports raw decision count, observed cluster count, overlapping horizon/event membership, minimum cluster support and the frozen block/cluster uncertainty method. A cluster count is not automatically an effective independent sample size; serial dependence can persist across days or events. A hundred decisions around five macro releases do not support `n=100` independent-event inference. Cluster definition, weighting and minimum support are frozen before outcomes; a later change is a new evaluation contract and cannot upgrade the old result. The existing EURUSD diagnostic resampled UTC dates; that does not establish independent dates or correct coverage for another hypothesis. Justify a new method using development evidence and labelled null/dependence simulations, without tuning it to validation results.

Check temporal boundaries using each case's full feature and outcome intervals. Development labels must have matured before selection/candidate lock and must not reach into reserved validation intervals. Fit normalization, thresholds and baseline selection on permitted development data only. A validation case may use a legitimate predecision lookback from the preceding period; blanket removal of all shared historical inputs is unnecessary. Purge development cases whose outcome intervals overlap the validation boundary and apply a declared boundary gap where dependence requires it; within-validation overlap follows the frozen dependence method. Reject unregistered post-freeze case filtering, outcome-driven holiday exclusions and replacement of missing cases; apply frozen eligibility rules while retaining and counting every scheduled case. This is a contract/compiler check, not a reason to rerun the consumed diagnostics.

## 6. Extend the same loop to Loop A

Once a decision/payoff contract and baseline agent version exist, reuse the registry, runtime, Critic and evaluator for one-component improvements. Register the parent decision target and payoff as fixed, the single permitted change (for example one prompt or typed question), development objective, candidate budget and untouched validation plan before a Research agent proposes variants. Critic examines source timing, likely failure modes and whether the variant actually preserves the parent's payoff. The contract service rejects target or payoff changes from Loop A and routes them to a linked Loop B hypothesis.

The evaluator compares the frozen variant to its registered baseline on the same predeclared cases and costs, records all attempts and failures, and releases results only after measurement. A promotion decision remains separate from evaluation and requires the normal prospective, risk and operator gates. The Loop A completion gate is a traceable baseline-versus-variant comparison on untouched evidence with every attempted variant counted; an improvement claim is not required. If the loop later uses Optuna or prompt optimization, it may search only a registered development space and cannot select against that validation outcome.

## 7. Risks and unresolved inputs

- **Holdout exhaustion and access:** the current raw CSV is accessible to offline research code. Enforce storage/process credentials and the exposure ledger before calling a new result independent. Historical source scans may measure presence without calculating candidate performance. An eligible but previously exposed window remains consumed; prospective collection is the fallback when no credible unused period exists.
- **Economic costs:** many 2020–2021 EURUSD rows have equal bid and ask, and executable spread/commission/slippage semantics remain unverified. The available 2026 statement has net results but no fee decomposition. An economic proposal may be stored and critiqued, but it cannot pass a net-payoff gate without a sourced, period-matched cost contract.
- **Model capability:** activate only a provider/model combination that passes the required text, typed-output and tool-call behavior. A valid JSON proposal is still a proposal, not evidence.
- **Trial accounting:** count all drafts, revisions, rejected contracts, failed evaluations and optimizer trials in their research family. A changed target, window, source, cost rule or success criterion after seeing results is a new linked attempt.
- **Historical timing:** backfilled 2020–2021 prices were obtained in 2026. Label any reuse as retrospective assumed visibility; preserve actual ingestion time and never describe it as recorded historical inference.
- **Inferential validity:** a reproducible calculation, cluster label or complete trial ledger does not certify valid uncertainty or discovery. Freeze and verify a method suited to the registered claim before increment 6; exploratory evidence stays exploratory.
- **Agent contribution:** two roles, plausible lessons and high agreement may still add cost without better research. The process suite measures the bounded catalog; transfer to semantic/news research and executable returns remains unmeasured.

## 8. Evidence behind this revision

This was a targeted, AI-assisted review of the plan and implemented contract/evaluator boundary on 09 October 2026, not an exhaustive systematic review or a trading experiment. Searches covered adaptive multiple testing, optional stopping, clustered uncertainty, temporal/model leakage, LLM critique/judging, reflection, agent benchmarking and tool-output injection. Relevant supporting passages were inspected, including evidence that reflection can help. Two separate source-review workers contributed within the same Codex model family; this is not cross-provider or human validation. Repository artifacts were read without recomputing market outcomes.
